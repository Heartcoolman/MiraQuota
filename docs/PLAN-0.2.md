# MiraQuota 0.2 收敛版规划

范围：不新增数据源、指标、窗口与交互入口。本轮只做四件事——既有口径的一致性、界面版式与动效、常驻开销、两个显示面（客户端控件与菜单栏面板）的能力对齐。

基线：控件 v12、`CFBundleShortVersionString` 0.1.0、源码与 `~/Applications/MiraQuota.app` 内容一致（`diff` 无输出）。

## 二、由观测导出的缺陷

1. **口径不一致（5h 卡）**：卡面并列 `$51.6 / $213` 与 `15.9%`，前者为账本支出 ÷ 回归标定满额（24%），后者为额度点比值。同一张卡上两个分母口径不同，进度条按后者绘制，金额按前者显示。7d 卡两者相差 1 个百分点，5h 卡相差 8 个百分点（各窗口点数计价不同）。
2. **宽度过渡从未生效**：`.bar .fill` 声明了 `transition: width .5s`，但每次绘制都替换 `pop.innerHTML`，新节点直接以终值挂载，过渡无起点。
3. **每秒重排清掉交互态**：展开态每秒重建全部子树，`#quit` 的 hover 高亮与 `transition: background .12s` 每秒被清一次并重新绑定 `onclick`。
4. **速度卡的提示在无实质变化时抖动**：`recentCount = 3` 使显示值随样本进出摆动，`drift` 的 ±10% 阈值恰在摆动幅度之内，「快 x%／慢 x%」的出现与颜色随轮次翻转。
5. **胶囊上一个圆点编码两个信号**：`dotClass` 由通道状态给出，随后又被 `toneClass(usedPercent)` 覆盖，用量 ≥80% 时圆点转橙，通道状态在胶囊上不再可读。
6. **7d_fable 在两个面上都未适配**：胶囊只显示 5h 与 7d；SwiftUI 面板 `WindowCard.title` 只映射 5h／7d，fable 窗口显示原始 label `7d_fable`。
7. **展开层无落位兜底**：固定 300×405，锚点恒在胶囊下方，空间不足时不翻转、不夹取；窗口尺寸变化后不重新落位。
8. **拖动无视口夹取**：`place()` 只夹取到 ≥0，窗口缩小后控件可停在可视区外，恢复只能靠清 localStorage。拖动过程中每个 mousemove 写一次 localStorage。
9. **时间与数位写法不统一**：控件写「6天1时」，Swift 侧写「6 天 1 小时」；菜单栏标题用 0 位小数，面板与控件用 1 位。
10. **菜单栏面板落后于控件**：面板缺剩余美元、打满外推、在途「生成中」、点数行；进度条无动画（`PanelView.swift` 内无任何 animation 声明）；`popover.contentSize` 初始 344×360 与三窗口内容不符，首次展开有一次尺寸校正；倒计时定时器在弹层收起后仍每秒触发（`onReceive` 内以 `visible` 挡住重绘，publisher 本身不停）。
11. **失联时无过期表达**：`state.err` 时胶囊只把圆点转灰，数字照旧显示，无龄期、无降饱和。
12. **动效未覆盖降级偏好**：控件 CSS 无 `prefers-reduced-motion` 分支。

## 三、分级清单

### P0 — 口径与开销

**P0-1 常驻开销收敛**
- 改动：`CostLedger.scanTranscripts` 拆为热集与全量两条路径。全量枚举降到 60 秒一次，热集为最近 10 分钟有改动的文件（实测最近 1 小时仅 8 个文件改动、其中 3 个大于 1 MB），轮间只对热集取属性；`SpeedStats.scanLedger` 补 mtime 闸门，与 `CostLedger.gatewayScanned` 同形；心跳按在途请求自适应，有在途 5 秒、空闲 20 秒（在途判定走 diag 游标，本身不受影响）；1 MB 尾读复用同一块缓冲，不每轮新建 `Data`。
- 验收：空闲 <1% 单核、有在途 <3%；RSS 稳定在 60 MB 以下；`--once` 与 `--doctor` 输出不变；速度卡新鲜度不退化（现为几十秒）。

**P0-2 控件改为增量绘制**
- 改动：骨架（三张窗口卡、速度卡、页脚）建一次并缓存节点引用，更新只写文本与 `style.width`；窗口集合变化时才重建对应卡片。
- 验收：宽度过渡实际发生（CDP 连续两帧截图宽度不同）；`#quit` 的 hover 在跨秒后保持；展开态每秒不再产生整树重排。

**P0-3 速度卡抖动收敛**
- 改动：`recentCount` 3→5；显示值加迟滞（新值与上次显示值差 <8% 时不更新显示）；`drift` 显示阈值提到 ±25% 且要求参与样本 ≥3；`rate` 超出 `baselineRate` 三倍时不显示 drift（该情形已实测到，rate 150 对 base 79）。
- 验收：以同一段账本重放，2 分钟内显示值变动 ≤2 次、色彩状态变动 ≤1 次；样本新鲜度显示不变。

**P0-4 5h 卡口径统一** — 已裁决为方案 A（按点数口径折算），见第五节。

### P1 — 版式与动效

**P1-5 三窗口版式**：金额列对齐（标签定宽或金额右对齐，现「5 小时／7 天／7 天 · Fable」宽度不同导致 `$51.6`、`$452`、`$51.6` 起始位置各异）；点数加千位分隔或改紧凑写法（现「24925/156800 点」）；5h 卡视觉权重略高于两个 7d 卡。

**P1-6 胶囊信号分离**：通道状态与用量档位各自成形（状态用点、用量用文字色）；补长窗口可见性，胶囊第二段改为「占比最高的长窗口」而非固定 7d；失联或数据超龄时降饱和并附龄期。

**P1-7 展开层落位**：下方空间不足时翻转到上方，右侧空间不足时夹取；`resize` 时重新落位；同时给拖动加视口夹取，窗口缩小后控件不出可视区。

**P1-8 动效补齐**：数值变化以淡入或一次性高亮表达，不做数字滚动；开合曲线与宽度过渡统一到同一组时长与 easing；补 `prefers-reduced-motion: reduce` 分支，降级为无过渡直接换值。

**P1-9 文案与数位统一**：时间单位统一为「天 / 小时 / 分钟」并统一数字与汉字间的空格；三处小数位统一（菜单栏标题、面板、控件）；「余 $x」「到重置不满」「≈N 后满」措辞收敛为一套。

**P1-10 面板补齐到控件同级**：`7d_fable` 标题映射；剩余美元与打满外推行；在途「生成中 N 条 · 已 M 秒」；点数行从悬浮提示提到卡面；进度条与百分比加动画；`popover.contentSize` 与三窗口内容一致；倒计时 publisher 在收起后停掉而非空转。

### P2 — 交互补齐（可整体取消）

- **P2-11 拖动手感**：`cursor: grab / grabbing`；localStorage 只在 mouseup 落盘一次；边缘吸附。
- **P2-12 交互补齐**：Esc 收起；展开层内允许选中复制数字（拖动仅绑在胶囊上，不冲突）；退出改为二次确认并给出退出后的静止态提示。
- **P2-13 注入器巡检退避**：命中且版本一致连续三轮后，巡检间隔 10s→30s，减少渲染进程侧的 CDP 往返。
- **P2-14 浅色主题实盘核对**：以独立 Chrome 加载浅色页面注入控件核对 `light` 调色板；该分支自实现以来未在浅色宿主上验证过。

## 四、明确不做

- 不加数据源、指标、窗口、通知、历史曲线、按模型成本分解。
- 不改 CDP 注入形态与五级降级阶梯的层级划分。
- 不改 `quota.json` 已有字段的含义（可增字段；P0-4 若选方案 A 则新增一个字段，不改旧字段语义）。
- 不改标定算法本身（两侧挂起、10 分钟超时、单价反推口径全部保留）。

## 五、已裁决：5h 卡的美元口径（取方案 A）

| 方案 | 卡面主行 | 代价 |
|---|---|---|
| A：按点数口径折算 | `已用 = 满额 × 用量百分比`，与进度条同分母；账本支出降为副行「账本 $51.6」 | 主行金额不再等于本机账本支出，须在悬浮提示里说明；`quota.json` 增一个字段 |
| B：保留账本支出 | 主行仍为账本支出与回归标定满额 | 5h 卡上 24% 与 15.9% 的并列继续存在，靠悬浮提示与百分比后缀标注口径 |

两者都不影响百分比与点数的准确性（`/v1/limits` 原始值）。

**裁决：方案 A**（2026-08-24）。主行改为 `满额 × 用量百分比`，账本支出降为副行「账本 $x」。
落地后实测同刻两者为 $54.6 与 $104（差 1.9 倍）：主行随百分比走、与进度条自洽，
但其绝对值继承回归标定的漂移；账本行是唯一与实际支出挂钩的数字，故保留在卡面而非提示里。
`--doctor` 的「满额互校 5h」告警（额度点口径 $599 对回归标定 $224）反映的是同一件事，
即各窗口点数计价不同且随用量构成漂移，不是本轮引入的问题。

### 与计划的偏离

- **未做自适应心跳**。原计划「空闲时 5s → 20s」，改为把每一轮本身做便宜（mtime 判新 + 活跃集）。
  理由：在途请求的发现延迟直接影响「生成中」的跟手程度，放慢心跳会拿这个换开销，
  而判新之后空闲一轮几乎不读盘，开销目标已达成，无须牺牲延迟。
- **多做了一项**：控件主题判定补了「宿主背景亮度」这一级。起因是实测本机系统外观为浅色而
  Mirasim 界面为深色（`data-theme=dark`），页面若哪天不再给该属性，只看系统偏好会把
  浅色控件贴到深色界面上。
- **未做缓冲复用**。加了 mtime 闸门后 1 MB 尾读只在文件真的变化时发生，RSS 高水位已从 91 MB 降到 65 MB，
  复用缓冲的收益不足以换取代码复杂度。RSS 仍在 49–65 MB 间往复，若要压平得改成常驻缓冲，留作后续。
- **速度抖动的验收未达成量化标准**。原定「2 分钟内显示值变动 ≤2 次」需要可重放的样本集才能判定，
  本轮只有在线采样，负载不可控。后续若要判定，得先做账本重放（把一段 `usage-*.ndjson`
  与 transcript 固定下来喂给 SpeedStats），本轮不做。
