# MiraQuota

macOS 菜单栏常驻插件，把 Mirasim 的 5 小时 / 7 天额度百分比换算成美元口径：满额大约值多少，当前窗口已经用掉多少。

> An unofficial macOS menu-bar (and in-client) widget that turns Mirasim's 5-hour / 7-day quota
> percentages into a dollar-denominated view. macOS 14+, built from source with a full Xcode.
> Not affiliated with Mirasim or Anthropic. Documentation below is in Chinese.

```
菜单栏    24.3% · $54.6

额度                                    精确

5 小时          $54.6 / $224            24.3%
████████▎──────────────────────────────────┃
余 $170                        重置 0:35:29
账本 $104 · 38.1k/157k 点

7 天             $522 / ~$2,222          23.5%
████████▎────┃─────────────────────────────
余 ~$1,700 · ≈1.1 天后打满        重置 6 天
账本 $504 · 132k/560k 点

7 天 · Fable    $61.9 / ~$1,137           5.4%
██▏──┃─────────────────────────────────────
余 ~$1,075                        重置 6 天
账本 $504 · 16.2k/297k 点

速度                    ● 生成中 2 条 · 已 19 秒
Opus 5    首 ≈4.0s · 80 tok/s        52 秒前
Fable 5   首 ≈6.1s · 48 tok/s 慢37%  74 分钟前

满额 回归标定优先 · 兜底 额度点 × $0.003804
999 分钟桶 · models.dev cache · cloud relay.mirasim.ai · ok
```

进度条上的竖线是均速游标。用量条越过它表示消耗快于线性速度。

**卡面主行是按点数口径折算的已用额度**（`满额 × 用量百分比`），与百分比、进度条同分母，
三者互相自洽；本机账本支出放在副行的「账本 $x」。两者的差值反映当前窗口的用量构成与
标定期不同（各窗口点数计价不同，实测 5h 上可差到 1.8 倍），故账本值保留而不是弃用。

## 前置条件

| 项 | 要求 |
|---|---|
| 系统 | macOS 14 或更新；Apple Silicon 与 Intel 均可（在本机构建本机架构） |
| 构建 | 完整 Xcode 16 或更新（Swift 6 工具链）。仅装 Command Line Tools 编不过，SwiftUI 的宏插件不在其中。`bundle.sh` 依次探 `DEVELOPER_DIR`、`xcode-select -p`、`/Applications/Xcode*.app`，找不到完整 Xcode 即报错退出 |
| Mirasim | 桌面版在本机运行。`/v1/limits` 于 v0.0.220 实测可用；旧版没有该端点时自动退回 relay 帧的百分比口径 |
| 客户端内控件（可选） | Mirasim 需带 `--remote-debugging-port` 启动，见「放进 Mirasim 界面」；不带则只显示菜单栏图标 |
| 美元口径 | 由本机账本折算，账本取自 `~/.claude/projects/*/*.jsonl`（Claude Code）与 `~/.mirasim/insights/usage-*.ndjson`（Mirasim 网关）。两处均为空时点数与百分比照常显示，美元金额与额度点单价不出 |

不提供预编译包：未经开发者签名的下载包会被 Gatekeeper 隔离，需手工去除隔离属性才能运行；
本地构建时 `bundle.sh` 做 ad-hoc 签名，不受此限。故安装路径只有一条——克隆后自行构建。

未适配 Windows 与 Linux：菜单栏、LaunchAgent、CDP 注入的落位逻辑均依赖 macOS。
Windows 上可参考 [chiakinanam1/mirasim-quota-widget](https://github.com/chiakinanam1/mirasim-quota-widget)，
它走的是注入 payload 目录 index.html 那条路。

## 边界与免责

- 非官方项目，与 Mirasim、Anthropic 均无关联，不代表任何一方。
- 读的是 Mirasim 的**本地未公开接口**（路由端口的 `/v1/limits`、`mirachannel` 的 WebSocket 帧）。
  接口随 Mirasim 版本变动即可能失效，届时按五级阶梯退让并在面板上标明当前级别，不静默显示错误数字。
- 不接触任何凭证，不发出对外网络请求，不写入 Mirasim 的任何文件；只读本机回环端口与本机账本文件。
- 客户端内控件走 CDP 注入。调试端口开着时，本机任何进程都能在 Mirasim 的渲染进程里执行 JS；
  端口只绑回环，但隔离度确实下降。不接受这个代价就不要启用控件，菜单栏图标不受影响。
- 美元数字是按本机账本折算的估计值，不是账单。绝对金额有系统性偏差（长上下文溢价未建模），
  且额度归 relay 账号池、本机用量不等于额度占用。据此做用量决策前先读「已知限制」。
- 按 MIT 许可发布，不提供任何担保。

## 安装

```bash
git clone https://github.com/Heartcoolman/MiraQuota.git
cd MiraQuota
./scripts/install.sh      # 构建、装到 ~/Applications 并注册 LaunchAgent
./scripts/uninstall.sh    # 卸载；加 --purge 一并删除标定数据
```

仓库位置不影响运行：`install.sh` 把应用拷进 `~/Applications`，之后移动或删除仓库都不会让自启指向空路径。

装好后登录即自动运行，无需手动打开。崩溃会被 launchd 拉起；从面板点「退出」是正常退出，
保持退出状态直到下次登录。首次安装后 macOS 会弹一次「App 后台活动」通知，属正常。

依赖完整 Xcode 构建（SwiftUI 的宏插件不在 CommandLineTools 里）。

**菜单栏图标不出现时**（`--doctor` 显示作业运行中，但看不到图标）：

```bash
launchctl kickstart -k gui/$(id -u)/local.miraquota
```

`rm -rf` + `cp -R` 重建 app 包会让 LaunchServices 的注册变陈旧，紧接着启动的那次进程
虽然把状态栏项建出来了（`button=true visible=true`），却拿不到菜单栏位置。
`install.sh` 已在末尾自动再踢一次作业规避；登录时的启动面对的是稳定的包，不受影响。

同理，`launchctl bootout` 是异步的，未等作业拆除完就 `bootstrap` 会以
`EIO` 失败。**不要回退到 legacy 的 `launchctl load`**——那样加载的 agent 进程能跑，
但同样拿不到菜单栏位置，表现为「装好了却没图标」。

## 数据来源

| 数据 | 来源 | 说明 |
|---|---|---|
| 已用额度点、总额度、重置时刻 | `http://127.0.0.1:<路由端口>/v1/limits` | 原始值，`used` 带小数位；本机免认证 |
| 额度百分比、重置时刻（退路） | `ws://127.0.0.1:<port>/mirachannel/ws` 的 `getRelay` 帧 | 与 Mirasim 界面同源，分辨率 0.1% |
| 等价支出 | `~/.claude/projects/*/*.jsonl` | Claude Code 全量 token，含 cache 分量与 model |
| 等价支出（补充） | `~/.mirasim/insights/usage-*.ndjson` | 只补 pi-gui 一类不经 Claude Code 的智能体 |
| 价目表 | `~/.mirasim/models-dev-cache.json` | 缺失时回退到内置表 |
| 请求时长 | `~/.mirasim/insights/usage-*.ndjson` 的 `durationMs` | 每次请求的总耗时，用于推出速度 |
| 在途请求 | `~/.mirasim/diag/ev-*.ndjson` 的 `model.begin` / `model.end` | 请求发出即落盘，用于显示「生成中」 |
| 实测首字节 | `~/.mirasim/analytics/events-*.ndjson` 的 `turn.finish.props.ttfbMs` | 仅覆盖 Mirasim 图形界面发起的对话，只作量级对照 |

`/v1/limits` 挂在 Mirasim 分给每个会话的回环端口上（即 Claude Code 拿到的
`ANTHROPIC_BASE_URL`），对本机放行，回传 `windows[].{name, used, budget, reset_at}`
与 `suspended`/`unmetered`/`degraded` 三个账号状态位。端点未公开，v0.0.220 实测可用；
路由端口由「持有 mirachannel 端口的那个进程」的回环监听口枚举得出，限定同一进程是为了
避免同时跑着开发实例时读到另一个账号的额度。该做法由
[chiakinanam1/mirasim-quota-widget](https://github.com/chiakinanam1/mirasim-quota-widget) 提示。

远端同名端点走不通：`https://relay.mirasim.ai/v1/limits` 需要 `device.privateKey`
的签名头，仅带 `setting.json` 的 auth token 返回 401。网关账本里的
`anthropic-ratelimit-unified-7d-utilization` 响应头仅存在于 2026-08-09 之前的旧
relay 记录，现行 `relay.mirasim.ai` 不再透传，且从未透传 `5h`。额度百分比本身不落盘，
只存在于 Mirasim 进程内存。故本插件只走 Mirasim 的本地接口，
**不接触任何凭证，不发出网络请求，也不写入 Mirasim 的任何文件**——
它对 Mirasim 而言只是一个只读的本地 WebSocket 客户端，不会导致 Mirasim 报错或无法启动。

## 满额怎么来

**首选口径：读原始值再折算。** `/v1/limits` 直接给出已用与总额的额度点数，
百分比即 `used / budget`，无需反推。美元数字仍需账本折算：额度点单价由
「窗口内账本支出 ÷ 已用点数」得出，取已用点数最多的窗口反推，两个窗口共用同一单价
（实测 5h 与 7d 各自推出的单价相差 1.2%，$0.004669 与 $0.004723，即 1 额度点约 0.47 美分）。
已用点数不足 200 时不反推单价，满额沿用下面的回归标定。

面板上 `$54.6 / $224` 的分母是该窗口自己的回归标定满额（端点可读时优先用它，
全局单价 × 预算点只作兜底并标低置信）；`24.3%` 与美元无关，是点数比值；
分子是二者相乘，故三个数字在卡面上自洽。本机账本支出另列一行。

**退路口径：由百分比反推满额。** `/v1/limits` 取不到时（旧版 Mirasim 无此端点）走下面这套。
两条路径互相独立，`--doctor` 会并列两者并在分歧超过 15% 时告警；实测差 1.9%（5h）与 0.0%（7d）。

额度百分比与 API 等价支出在窗口内呈线性关系，满额由「一段时间的支出 ÷ 同期百分比增量」反推，
样本越多越准。百分比只精确到 0.1%，故支出与百分比增量**两侧都要挂起**，等对面也非零时
才成为一次观测：

- 只挂起支出（百分比不动时累积美元）：逐对丢弃零增量样本会系统性低估满额约 60%。
- 只挂起百分比（支出未落账时累积增量）：账本按请求完成时刻计费，有请求在途时百分比先涨、
  美元后落，丢掉这些增量等于少算分母。实测 5 小时窗口上有 91/270 步属此情形、
  合计 12.7 个百分点，满额因此高估约三成（$261 对整段口径的 $202）。这 91 步在区间内
  **全部有本机请求在途**（并发中位 2 条），支出在其后中位 1 分钟落账，故判为归属滞后，
  而非账号池他人占用；挂起超过 10 分钟仍无支出则丢弃，避免把他人的占用记到本机美元上。

并行请求会放大后一种情形：按同期平均并发把观测分组，只挂起支出时低并发段推出 $302、
高并发段推出 $211；两侧都挂起后分别为 $207 与 $204，并发依赖基本消失。

冷启动时会导入 relay 帧自带的百分比环形缓冲（约 120 点 / 76 分钟），无需从零等待。
逐对隐含满额的两端各 10% 会被裁掉，以剔除账号池共享造成的百分比跳变。

置信度按标定覆盖的百分比跨度与观测数判定，满额未达高置信时以 `~` 标记。

标定值可用推算与实测的一致性反查：强制离线后由「本机支出 ÷ 满额」得到的百分比应接近
relay 实测值。修正后 $20.21 / $206 = 9.8%，与同刻实测的 9.8% 相符；修正前的 $261 会给出 7.7%。

## 出字速度与首 token 怎么来

本机没有任何文件记录单次请求的首 token 时刻：transcript 只有消息落盘时间，网关账本只有总时长。
同一模型上总时长与输出量近似线性

```
时长 ≈ 首 token 等待 + 输出量 ÷ 出字速度
```

故按窗口内的请求回归，斜率给出字速度，截距给首 token 等待。首 token 因此标 `≈`。

- **口径**：出字速度只看**最近 5 次**请求，按 token 加权，并对显示值做一阶平滑
  （系数 0.35，与上次显示值相差超过 60% 时判为工况切换直接跳过去）；
  首 token 取 48 小时内全部样本的回归截距。
  两者时间尺度不同是有意的：首 token 无法逐次测量，样本少了撑不起回归；出字速度要跟手，
  取整窗口的中位数会被几百条旧样本淹掉（实测新增一条对中位数的影响不到 1%）。
  取 3 次且不平滑时实测显示值在 145 秒内于 67–83 tok/s 间摆动，「快/慢 x%」的提示
  五次穿过阈值，看着像在抖。
- **加权而非中位**：几十 token 的短请求里首 token 占了大半时长，逐条比值噪声极大
  （实测同一段时间内逐条落在 32–101 tok/s）。按 token 加权后长请求自然占主导，新样本一到就推动结果。
- **新鲜度**：行右侧显示最近一次请求距今多久。出字速度是逐次请求的量，只有请求完成、账本落账后才更新，
  故没有新请求时数字本该不动；把新鲜度显出来，免得看着像界面卡住。
- **生成中（实时）**：请求还在流、尚未完成时，速度卡顶部显示脉冲点与「生成中 N 条 · 正在生成：已 M 秒」。
  这来自 Mirasim 的诊断事件流 `~/.mirasim/diag/ev-*.ndjson`：`model.begin` 在请求发出的瞬间落盘，
  `model.end` 在完成时落盘，两者按 `callId` 配对，未闭合的即在途。中断的请求不发 end，故在途超过
  10 分钟即判弃（已闭合请求实测 95 分位 46 秒、最长 383 秒）。有请求在途时控件轮询提到 2 秒、
  「已 M 秒」逐秒走动；请求一完成，出字速度随下一次账本落账更新。这样「一边用一边算」在界面上可见。
  出字速度本身仍是完成后才算的量——响应流式过程中本机没有 token 计数可用，能实时看到的是「在生成、已多久」。
- **偏离提示**：「快 / 慢 x%」的闸门是「样本 ≥3、幅度进 25% 出 18%、当下值不超过基准三倍」。
  阈值分进出两档是为了不在边界上闪：贴着单一阈值时每轮微小变动都会让提示出现又消失；
  三倍上限挡掉样本构成突变（实测出现过 150 tok/s 对基准 79）。
- **显示名**：账本里是 `claude-opus-5`、`claude-opus-4-8`、`claude-haiku-4-5-20251001` 这类原始名，
  界面显示 `Opus 5`、`Opus 4.8`、`Haiku 4.5`（去 `claude-` 前缀与快照日期，族名首字母大写，版本用点连接）。
  版本段不是纯数字时（`gpt-5.6-sol` 一类）原样保留，不按猜测拼名字。
- **分模型**：混合模型统计会明显偏移（实测全模型合计得 1.4s / 60 tok/s，而单取 opus-5 得 4.5s / 81 tok/s），故按模型分行，最多三行。
- **估计方式**：按输出量排序后取跨半程配对的斜率中位数（确定性的 Theil–Sen 变体），对重试与网络抖动一类的离群时长不敏感。输出量相同的样本按时长再排一次，否则并列样本的配对顺序会随排序实现变化，中位数漂移数个百分点。
- **门槛**：回归需同模型 ≥12 条样本才给首 token；最近样本不足 2 条或最近一次请求超过 2 小时则不成行。
  没有首 token 时只报端到端速率（输出量除总时长，含首字等待）。回归截距为负时同样只报速度。
- **筛选**：仅 `status == 200`、输出量 ≥32、时长 ≥200ms。账本里 token 未回填的记录（约三成）不计入；其时长中位数 9.0s 与入选记录的 10.2s 接近，剔除不引入方向性偏差。
- **不等回填的三方关联**：账本记录落盘即时，但 token 要等 relay 回填（落盘时 `output` 为 0，回填要几十秒到数分钟），
  且回填会**原地改写历史行**（实测同长度前缀的 md5 数秒内即变）。只读账本必然滞后甚至永久丢样本。
  故 token 与时长都改从即时来源取，用账本记录做关联枢纽：

  | 取什么 | 来源 | 关联键 |
  |---|---|---|
  | 关联枢纽、模型、时刻 | `insights/usage-*.ndjson`（尾部重扫 1 MB，按 `id` 去重） | — |
  | 输出 token（即时） | `~/.claude/projects/*/*.jsonl` 的 `message.usage.output_tokens` | 账本 `providerCallId` == transcript `requestId` |
  | 请求时长（即时） | `diag/ev-*.ndjson` 的 `model.end.durationMs` | 账本 `id` 冒号后半段 == diag `callId` |

  实测回填后的记录里，账本 `output` 与 transcript token 逐条相等（134/159/292/987），可见口径一致；
  而尚未回填的记录账本为 0、transcript 已有值，正是靠这一路把新鲜度从几十分钟压到几十秒。
  **绝不能对账本用单向游标**：越过的行在回填后再也读不到。
- **稳定性**：实测 856 条 opus-5 记录按 150 条连续分段，首 token 落在 2.3–4.6s，出字速度 73–95 tok/s，OLS 的 R² 为 0.71–1.00；样本降到 20 条仍给出 3.5s / 83 tok/s。
- **并行**：`durationMs` 是每条请求自己的墙上时间，重叠不改变回归的结构，只带来链路争用的偏移。
  实测 39.5% 的请求与其他请求在时间上重叠；同一批 opus-5 样本按重叠程度分组，独占（540 条）
  得 3.65s / 83.7 tok/s，有重叠（351 条）得 3.08s / 76.3 tok/s，重度重叠（≥3 条，58 条）
  得 3.21s / 75.8 tok/s。争用使出字速度低约 9%，落在分段波动区间内，故不按并发度分别展示。
- **对照**：提示浮层里附上 Mirasim 自己测的 `turn.finish.ttfbMs` 中位数。它是整轮首字节而非单次请求，且只覆盖图形界面发起的对话（两天共 7 条），只能作量级对照。

出字速度不含首字等待，故高于端到端速率。两者与首 token 自洽：`首 token + 输出量 ÷ 出字速度` 应接近观测到的时长中位数（实测 4.5 + 460/81 ≈ 10.2s，观测中位 9.7s）。

## 放进 Mirasim 界面

控件长在 Mirasim 的界面里，不改 Mirasim 的任何文件：

```bash
./scripts/mirasim-debug.sh          # 退出并以 --remote-debugging-port=9333 重开 Mirasim
```

之后 MiraQuota 每 10 秒巡检一次 CDP 端点（稳定后退避到 30 秒），把
`Contents/Resources/widget.js` 送进渲染进程（`Page.addScriptToEvaluateOnNewDocument`
覆盖此后每次导航，`Runtime.evaluate` 补上当前这次），控件出现在界面右上角。

控件的交互：拖动移位（松手时才落盘，位置夹在视口内）、**拖到标题栏空位即吸附**、点胶囊或按 Esc 开合、
展开层在下方装不下时翻到上方、层内文字可选中复制、「退出」需点两次确认。
吸附位取「标题栏上不与宿主控件重叠的最右一段空位」：Mirasim 自己的标题栏右侧排着波形、
`29% 云端`、分支、复制等控件，控件贴右上角会压在上面。落位靠命中测试在标题栏带上从右往左扫，
遇到第一段能放下胶囊的空白即停（实测本机空白段为 x 415–875，胶囊落在 695–877，与宿主控件留 8px）。
竖向位置按**宿主底色的连续段**居中，不按 header 元素高度：Mirasim 的 header 是 28px，其下还有约
6px 同色区域，眼睛看到的是一整条约 34px 的深色带，按 28 居中会贴着窗口上沿（上 3px、下 9px）。
落位时自顶向下逐像素比对生效背景色，取相同底色的连续段作为带高，胶囊在带内居中。
判定命中的条件是「竖向贴着标题栏（±16px）」且「横向在吸附位左右 140px 内，或该落位会压住宿主控件」——
压住宿主控件的位置本来就不该停。吸附后只存一个标志，坐标每轮重算，故窗口缩放、标签增减、
宿主控件出现或收起时控件跟着走；拖离即解除，之后按存下的坐标落位。

主题按 `data-theme` → 宿主背景亮度 → 系统偏好三级判定（本机系统为浅色而 Mirasim 界面为深色，
只看系统偏好会把浅色控件贴到深色界面上）。系统开启「减弱动态效果」时所有过渡与脉冲关闭。
骨架只建一次、更新只改文本与宽度，故进度条的宽度过渡真正生效，hover 与选区也不会每秒被清掉。

**客户端里有控件时菜单栏图标自动收起**，注入不可用（Mirasim 未带调试端口启动）时再放出来，
任何时候都至少有一处能看到额度。

数据不走文件：菜单栏进程在 `http://127.0.0.1:4988/quota.json` 上挂一份算好的 JSON
（4988 被占时向后顺延到 4995；只绑回环，只读），控件用 `fetch` 每 5 秒取一次。
控件失联时会在该区间内自行重找端口，持久注入脚本里烤着的旧端口不会造成失联。
另有 `POST /quit`，须带 `X-MiraQuota-Token` 头（令牌在 `~/.miraquota/feed.token`，
0600，首启生成）：回环端口上任何网页都能发出请求，GET 或裸 POST 会被浏览器
不经预检直接送达，无令牌校验时任意被访问的网页都能把本应用关掉。
渲染进程读不到 `~/.claude/projects` 与网关账本，美元与速度只能这样喂过去。

为什么走 CDP 而不是改文件：

| 路子 | 结论 |
|---|---|
| 注入 `~/.mirasim/app/<版本>/{renderer,web}/index.html` | 本机跑的是应用包里的版本（主进程打开的是 `app.asar`），payload 目录里的 0.0.151 没被加载，注入无效 |
| 改 `app.asar` | Electron fuse `EnableEmbeddedAsarIntegrityValidation` 是关闭的，改包不会被校验拦下，但会破坏应用签名，且每次更新被覆盖 |
| CDP 注入 | 不碰 Mirasim 的文件，升级不失效；代价是启动参数要带调试端口 |

渲染进程的 CSP 是 `script-src 'self'`，普通 script 标签加载不了外部脚本；CDP 执行的代码不受
CSP 约束，而 `connect-src` 明确放行 `http://127.0.0.1:*` 与 `ws://127.0.0.1:*`，故控件能回来取数。

**代价要说清**：调试端口开着时，本机任何进程都能在 Mirasim 的渲染进程里执行 JS。端口只绑回环，
但这确实降低了该应用的隔离度。不想要就别跑那个脚本——控件不出现，菜单栏图标照常显示。

## 读不到时怎么办

通道不可用时按五级阶梯逐级退让，任何一级都仍有可读输出。面板顶部的状态标签与横幅
说明当前处于哪一级、数字从哪来。

| 级别 | 触发条件 | 数据来源 | 标记 |
|---|---|---|---|
| 精确 | 路由端口的 `/v1/limits` 可读 | 原始额度点，百分比为 `used / budget` | 绿点 |
| 实时 | 端点不可读但 relay 帧持续到达 | 帧里的百分比，分辨率 0.1% | 青点 |
| 已过期 | 连接尚在但帧停更 | 最后一次实测值 | 黄点 |
| 推算 | Mirasim 未运行或不可达 | 落盘的窗口锚点滚动 + 本机账本 | 橙点，百分比前加 `≈` |
| 本地 | 从未取得过锚点 | 最近 5 小时 / 7 天的滚动窗口支出 | 灰点，无重置倒计时 |

窗口是固定窗口，只要实测过一次重置时刻，之后每个窗口的边界都能由
「重置时刻 + 整数倍窗口长度」推出。锚点落在 `~/.miraquota/anchor.json`，
因此 **Mirasim 完全关闭时插件仍给出可用估算**。

5 小时窗口的边界由窗口内第一次请求锁定：零用量时段 relay 报的 resetAt 等于
「采集时刻 + 5 小时」，每次轮询都是新值（实测 `resetAt - capturedAt` 恒为 300 分钟，
锁定后降到 238–248 分钟）。这类未锁定的取值不触发锚点落盘，离线推算沿用最后一次锁定的边界；
若离线期间跨过一个零用量窗口，推算的边界最多可偏一个窗口长度。推算值只反映本机支出，
不含账号池中他人的占用，故偏低，恢复实时后百分比通常会跳高。

Mirasim 若更新后改了帧格式，解析会按候选键名逐个回退，并在常规路径落空时对帧做一次
有界深搜；嵌套层级、键名、百分比用小数还是整数、时间戳用 ISO 还是毫秒，都不影响取值。
小数与整数按整帧证据判定：窗口与历史缓冲的取值全部落在 (0,1] 才按小数换算——逐值判断
区分不了「真实的 0.4%」与「小数的 0.4」，而刚重置的窗口恰好常落在该区间，历史缓冲里
重置前大于 1 的旧值足以判定刻度。换算后不在 0–100 的取值一律不显示；深搜命中额外要求
数值像百分比、重置像将来的时刻，防止帧内碰巧同形的无关数组（点数余额一类）被当成窗口。
实测可用 `scripts/fake-mirasim.py` 复现：

```bash
python3 scripts/fake-mirasim.py renamed &   # 换嵌套、换键名、小数占比、毫秒时间戳
MiraQuota --port 4979 --once                # 仍应解析出两个窗口
python3 scripts/fake-mirasim.py garbage &   # 帧完全无法识别
MiraQuota --port 4979 --once                # 应报「协议不符」并转入推算
```

真实 Mirasim 同时运行不影响该验证：`/v1/limits` 的探测严格限定在持有锚点端口的
那个进程上，伪实例不持有该端点，真实实例的端点也不会来抢答。

真的解不出来时，插件报「协议不符」并转入推算模式，不会静默显示错误数字。

## 排查

```bash
MiraQuota --doctor        # 逐项检查链路，指出断点与处置办法
MiraQuota --once          # 采集一次并打印
MIRAQUOTA_DEBUG=1 ...     # 打印通道收到的原始帧
MIRAQUOTA_OFFLINE=1 ...   # 强制离线，验证降级路径是否可用
MIRAQUOTA_SPEED_SPAN=45   # 覆盖速度统计的窗口长度（秒），验证样本不足的退化分支
MIRAQUOTA_NO_LIMITS=1     # 屏蔽 /v1/limits，验证退回 relay 帧百分比那一级
MIRAQUOTA_CDP_PORT=9333   # 指定 Mirasim 的调试端口（默认试 9333、9222）
MIRAQUOTA_WIDGET=<路径>    # 指定控件脚本，开发时免去重新打包
```

端口发现顺序：`--port` 参数 → 4970 → 从 `ps` 解析 `server.cjs serve --port N`，
逐个用 `/api/health` 校验；连续失败后额外扫 4970–4980。

## 已知限制

**额度是共享的。** 云端线路下额度归 relay 账号池，不由本机独占。历史 19 次 429 中有 2 次
发生在本机 5 小时窗口支出为 $0 的时刻，即额度被账号池其他使用者消耗。本机用量因此
不等于额度占用，标定出的满额反映的是「本机实际能用到的份额」，低于独占订阅的理论满额。

**额度点与美元是两套单位。** `used`/`budget` 是 Mirasim 自己的计量单位，百分比由它们相除
得出，与美元无关。美元数字要靠账本折算，因此单价、满额、已用金额都继承账本自身的偏差；
`/v1/limits` 端点未公开，Mirasim 改动后可能失效，届时自动退回帧口径。

**绝对金额有系统性偏差，占比不受影响。** 长上下文溢价未建模，故美元数字偏低。
但标定与计量共用同一张价目表，比例一致，占比与均速结论不受该偏差影响。

**速度是回归估计，不是测量值。** 首 token 与出字速度都由「时长对输出量」的回归得出，
不是逐次请求的实测值。时长里含 relay 转发与网络往返，故估出的首 token 高于模型自身的首字延迟。
思考 token 计入输出量，长思考会把出字速度算得偏高。并行请求在链路上互相争用，重叠样本的
出字速度低约 9%，卡片上的数字是两种情形的混合。

**控件依赖调试端口。** Mirasim 以普通方式启动时没有 CDP 端点，控件不会出现，
此时菜单栏图标自动放出来兜底。Mirasim 每次重启都需带该参数，`mirasim-debug.sh` 只作用于这一次启动。

**7 天窗口需要时间收敛。** 7d 百分比在短时间内变化极小，分辨率不足。5h 通常几十分钟即达高置信，
7d 需要累积数天样本。

**两个窗口可能显示相同的已用金额。** 5h 与 7d 的窗口起点若同时开启（同一批请求触发），
`resetAt - 窗口长度` 得到的起点相同，已用金额自然相同。这是固定窗口机制的正常结果。

## 常驻开销

心跳 5 秒一轮，一轮里的文件工作按判新收敛，空闲时几乎不读盘：

| 项 | 判新方式 |
|---|---|
| transcript（本机 2038 个 `.jsonl`） | 目录 mtime 发现新会话 + 近 15 分钟活跃文件重取属性，全量枚举 5 分钟一次兜底 |
| 网关账本、速度账本 | 文件 mtime 未变即跳过（回填会改写历史行，故判 mtime 不判长度） |
| 诊断事件、analytics | 字节游标增量读 |

逐轮对全部会话文件取属性的旧做法约合每秒 400 次属性读取，实测常驻 CPU 4.5% 单核、
RSS 在 61–91 MB 间往复；收敛后同法测得 1.7–1.8%，RSS 在 49–65 MB 间往复
（仍有往复是每轮 1 MB 尾读与字典重建所致，只在文件真的变化时发生）。

注入器在「全部页面都带着最新控件」连续三轮后把巡检间隔从 10 秒放到 30 秒，
任何一轮落空立刻回到 10 秒，改完控件仍能很快被顶上去。

## 状态文件

| 路径 | 内容 |
|---|---|
| `~/.miraquota/ledger.json` | transcript 读取游标、分钟级成本桶、requestId 去重表、网关账本的按 id 账目（保留 8 天） |
| `~/.miraquota/calibration.json` | 百分比样本序列（保留 14 天，每窗口上限 4000 条） |
| `~/.miraquota/calibration.lock` | 标定落盘的文件锁：常驻实例与 `--once` 并发写时防互吞 |
| `~/.miraquota/anchor.json` | 最后一次实测的窗口锚点，供离线推算；未锁定的取值不覆盖已锁定边界 |
| `~/.miraquota/feed.token` | 本机接口 `/quit` 的令牌（0600，首启生成，跨启动稳定） |
| `~/.miraquota/instance.lock` | 单实例锁，避免两份进程互相覆盖标定样本 |
| `~/.miraquota/agent.log` | LaunchAgent 的标准错误输出 |

百分比未变的样本不落盘：零用量时段 5h 的 resetAt 每次轮询都不同，若把它计入判重，
空闲一天会写入约 4300 条占位样本，把真实样本挤出 4000 条上限。实测过滤前后满额估计一致
（$205.8 / 146 观测），样本量由 1025 条降到 279 条。

首次建账要过约 1 GB 的 transcript，耗时约 1.5 秒；此后 transcript 按文件游标增量读取，
每轮只解析新增行。`requestId` 去重是必需的——fork 与 resume 会把父会话的消息
复制进新文件，不去重会重复计入。网关账本不走游标（行会被回填原地改写）：
每轮重扫尾部 1 MB，按 `id` 记账，token 回填使金额变大时把差额补回原分钟，
token 未回填的行不入账也不置已见，等回填后重读。标定样本落盘前先取文件锁、
并回磁盘上已有的样本，两个实例同时写也不会互相丢数据。
